- 日期: 2026-10-10
- 干草堆: 确定性生成,12 针 = 252,728 tokens;20 针 = 252,900 tokens(两次完全相同,可逐字节对比)
- 单卡 RTX 5060 Ti 16 GB;提问时 `reasoning_effort=none`(关闭思考)
- 判定: 答案中出现该针的精确访问码

## 0. 两个 .bat 的真实差异(仅此两行)

| | `start-llama-server.bat`(原版) | `start-llama-server - 副本.bat`(副本) |
|---|---|---|
| `--kvmem-action-lrfu --kvmem-lrfu-lambda 0.50 --kvmem-lrfu-top-frac 0.90` | **有** | **无** |
| `--kvmem-score-agg max` | **有** | **无** |

其余完全相同(同模型、`-c 262144 -n 16384 -b 512 -ngl 99`、`--kvmem-budget 36864`、
`--kvmem-gen-reserve 16384`、`-ctk/-ctv q8_0`、`--spec-type draft-mtp --spec-draft-n-max 3`、
thinking medium + rbudget 8192)。因此这是**干净的 A/B**:ActKV 的 LRFU 动作导向驱逐 +
GQA 头 max 聚合 开 vs 关。

## 3. 为什么两者分不开

当前设置下**测试处在天花板上**:

- 窗口 = 36,864 tokens = **288 个 128-token 块**;
- 20 根针只占 20 个块(约 7% 的窗口容量),而且针句与问题**共享关键词**,
  余弦检索几乎必中;
- 因此两个配置都能 100%,差异只可能出现在更吃紧或更容易混淆的场景。

### 想真正分开两个配置,建议按下面任一方式加难(我可以直接跑)

1. **针数逼近窗口容量**:100 根 → 200 根(288 块为上限),逼检索排序犯错;
2. **砍预算**:`--kvmem-budget 8192`(64 块)或 `4096`(32 块),让 20–40 根针去抢窗口
   ——这对 LRFU 的时序累积最敏感;
3. **去掉词汇重叠**:针句改成与问题无共同词的表述(如针句 "the marlin checkpoint uses
   UMBER-212",问题问 "what is the access code for the ninth depot?"),测语义检索而非关键词匹配;
4. **长针**:每根针写成一整段(数百 token),挤占窗口;
5. **多轮压力**:同一会话里连问 50+ 轮,观察 LRFU 的跨轮累积是否随时间改变选择
   (这是 ActKV 的卖点,单轮问 20 题测不出来)。
