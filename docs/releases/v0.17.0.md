# v0.17.0 — source release / 源码版本

This release covers changes merged into `master` after `v0.16.0-rc3`, through
commit `b8ad6de`. The existing rc3 CUDA and ROCm beta 2 downloads were built
from earlier source and do not contain all changes below. No v0.17.0 binary
package is announced here.

本版本汇总 `v0.16.0-rc3` 之后合入 `master` 的改动，范围截至提交
`b8ad6de`。现有 rc3 CUDA 与 ROCm beta 2 下载包基于较早源码，未包含以下全部
功能。本文不宣称已有 v0.17.0 二进制运行包。

## English — core features

1. **Multiple conversation KV caches, with optional NVMe spill.** One server
   retains several conversations' host KV histories and reuses a matching
   prefix when a conversation resumes. `--kvmem-conversations` sets the session
   count; a soft RAM limit and optional NVMe quota move inactive sessions by
   LRU. The active session remains in RAM. Requests still run one at a time,
   and disk snapshots are valid only within the current server process, not
   across restarts. On startup, the server reclaims orphaned cache files from
   marked, unlocked prior runs while preserving live servers' files. Unmarked
   legacy directories and files that fail deletion are left in place and
   reported. [RAM cache](../multi-conversation-kv-cache.md) ·
   [NVMe cache](../session-disk-cache.md)
2. **Experimental CUDA multi-GPU inference.** Opt-in `layer` and `tensor`
   splitting support two explicitly selected CUDA GPUs with one logical KVMem
   history. Layer mode keeps each attention layer's KV on its owning GPU;
   tensor mode uses llama.cpp's Meta-device KV shards rather than duplicating
   the full KV history. Both currently use synchronous KVMem transfers. MTP
   modes differ by split mode; row split and mixed backends are unsupported.
   [Layer mode](../multi-gpu-layer.md) · [Tensor mode](../multi-gpu-tensor.md)
3. **Independent vision-projector placement.** `--mmproj-device` chooses CPU or
   a named GPU for the vision projector without changing the language model's
   device placement. CUDA builds can also select a Vulkan GPU for the projector
   when built with Vulkan support. [Device guide](../mmproj-device.md)
4. **OpenAI Responses API.** `/v1/responses` and `/responses` accept
   non-streaming requests and SSE streams, including function-call output and
   image input through the existing vision pipeline when `--mmproj` is loaded.
   File IDs are unsupported; image `detail` is controlled by server settings.
   [API notes](../../README.md#apis)
5. **Experimental ROCm support on Windows and Linux/WSL2.** Native HIP builds
   and launchers use the KVMem adapter and GDN replay path. The latest build
   scripts also discover distribution-provided LLVM, honor compiler overrides,
   and can build without Ninja. GPU and toolchain compatibility still depend
   on the installed ROCm SDK; existing beta 2 packages precede this tag.
   [ROCm guide](../rocm.md)
6. **Long-running workload fixes.** The Linux IQ3/IQ4 launcher caps glibc
   allocator arenas by default to reduce observed RSS growth. This release
   also includes CUDA layer-capture read batching, multimodal replay-budget
   corrections, and CUDA KV-layout/OOM recovery fixes. These are targeted
   reliability and overhead improvements, not a new universal performance
   claim. [Host-memory diagnosis](../host-memory-arena-diagnosis.md) ·
   [Capture batching](../multi-gpu-layer-harvest-batch.md)

## 中文 — 核心更新

1. **多 Session 长对话 KV 缓存，可选 NVMe 转存。** 单个服务可保留多个对话的
   主机端 KV 历史；切回对话时，匹配已有前缀并复用缓存。
   `--kvmem-conversations` 控制会话数量，内存软上限与可选 NVMe 配额按 LRU
   转存不活跃会话。活动会话仍需完整驻留内存，请求仍是逐个执行。磁盘快照仅在
   当前服务进程内有效，重启后不会自动恢复。启动时会回收已标记、未被其他服务
   占用的旧运行目录，同时保留仍在使用的缓存。未带标记的旧版目录和删除失败的
   文件会保留并记录。
   [内存缓存](../multi-conversation-kv-cache.md) · [NVMe 缓存](../session-disk-cache.md)
2. **实验性 CUDA 双卡推理。** 显式选择两张 CUDA 显卡后，可按 `layer` 或
   `tensor` 模式分卡，并共用一份逻辑 KVMem 历史。Layer 模式将各层 KV 放在
   所属显卡；tensor 模式使用 llama.cpp Meta 设备的 KV 分片，不在两卡各复制
   一份完整历史。当前 KVMem 传输以同步方式运行；MTP 约束随模式不同。暂不
   支持 row 分卡或混合后端。[Layer 模式](../multi-gpu-layer.md) ·
   [Tensor 模式](../multi-gpu-tensor.md)
3. **视觉投影器独立选卡。** `--mmproj-device` 可让视觉投影器使用 CPU 或
   指定显卡，而不改变语言模型的设备分配。启用 Vulkan 支持的 CUDA 构建还可
   将视觉头放到 Vulkan 显卡。[设备说明](../mmproj-device.md)
4. **OpenAI Responses API。** `/v1/responses` 和 `/responses` 支持非流式
   请求及 SSE 流式事件，包含函数调用输出；加载 `--mmproj` 后，图片输入复用
   现有视觉处理路径。暂不支持文件 ID；图片 `detail` 由服务端设置控制。
   [API 说明](../../README.md#apis)
5. **实验性 Windows 与 Linux/WSL2 ROCm 支持。** 原生 HIP 构建和启动脚本
   接入 KVMem 与 GDN replay。最新构建脚本可发现发行版提供的 LLVM、遵循
   编译器覆盖设置，并在无 Ninja 时构建。具体显卡和工具链兼容性仍取决于本机
   ROCm SDK；现有 beta 2 包早于本 tag。[ROCm 指南](../rocm.md)
6. **长时间运行的稳定性修复。** Linux IQ3/IQ4 启动器默认限制 glibc
   allocator arena 数量，缓解已观测到的 RSS 持续增长；同时包含 CUDA layer
   捕获读回合批、多模态 replay 预算修正，以及 CUDA KV 布局与 OOM 恢复修复。
   这些是针对性的稳定性和开销改进，不代表所有配置均有统一性能提升。
   [内存诊断](../host-memory-arena-diagnosis.md) ·
   [捕获合批](../multi-gpu-layer-harvest-batch.md)
